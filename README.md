# ETF 分析与交易辅助系统

这是一个面向 A 股场内 ETF 的本地分析项目。它在原项目的行情同步、策略回测和模拟盘基础上，增加了全市场清洗、三类机会分析、ETF 风险检查、行动建议、持仓跟踪和中文 Excel 报告。

系统回答的是下面几类问题：

- 全市场中哪些 ETF 具备继续研究的条件；
- 值得关注的 ETF 属于趋势、反弹还是防守机会；
- 当前价格位置是否已经形成可执行的买入信号；
- 已登记持仓的原买入理由是否仍成立，是否需要观察、减仓或退出。

它不会预测明天涨跌，不会自动连接券商，也不会自动下单。策略结果、回测和行动标签都是辅助信息，最终决定由使用者作出。

## 项目来源与许可证

本项目基于 [zhuleimed/etf-daily-sync-and-backtest](https://github.com/zhuleimed/etf-daily-sync-and-backtest) 二次开发，并保留原项目的同步、策略、回测和模拟盘结构。

仓库使用 MIT License，许可证正文见 [LICENSE](LICENSE)。二次开发新增的主要能力集中在 `etf_universe` 模块。

## 当前处理流程

```text
更新本地 ETF / 指数日线
        ↓
价格断层检查与分析口径修正
        ↓
全市场基础筛选与同类去重
        ↓
策略信号与历史验证
        ↓
趋势 / 反弹 / 防守三赛道
        ↓
大盘状态 + 市场结构判断
        ↓
ETF 结构风险 + 当前交易风险
        ↓
关注价值与可执行信号分开判断
        ↓
持仓理由检查与卖出提醒
        ↓
中文 Excel 与 Markdown 报告
```

系统不会直接从约 1600 只 ETF 中选前三。大量产品跟踪相同指数，部分产品成交、规模或历史长度不足；同时，趋势、超跌反弹和低波防守的判断条件并不相同。先清洗、去重，再按不同赛道评估，可以减少重复产品和策略数量不平衡带来的偏差。

## 主要模块

| 目录              | 用途                                              |
| ----------------- | ------------------------------------------------- |
| `etf_sync/`     | ETF 名单、ETF 日线和主要指数日线同步              |
| `strategies/`   | 原有独立策略、回测入口和策略报告                  |
| `simulation/`   | 原有模拟盘框架和策略每日运行入口                  |
| `etf_universe/` | 全市场筛选、三赛道、风险、行动、持仓与 Excel 汇总 |
| `tests/`        | 数据质量、筛选、赛道、风险、报告与持仓规则测试    |
| `data/`         | 本地数据库、配置、人工持仓和分析输出              |

`python -m strategies.momentum_vol_filter.run` 这类命令只运行某一个原有策略自己的回测或报告。`python -m etf_universe` 会从全市场候选池统一调用可参与比较的策略，并汇总成三赛道结果，两者用途不同。

## 数据同步与质量

ETF、上证50、沪深300、中证500、中证1000等日线存放在 `data\etf_daily.db`。同步以 Tencent 为主源，单只产品失败时会尝试 Sina 备用源。主源请求前复权行情；备用源缺少稳定复权标记，因此备用源只补新日期，不覆盖已存在的重叠历史。

分析前会检查单日绝对跳变达到20%的价格。符合常见拆分比例且校验后的实际变化合理时，系统只修正分析用价格；无法解释的极端点会被隔离。原始日线不被覆盖。异常记录分为“已外部确认、自动规则修正、待人工核验”，并写入“数据异常检查”Sheet。自动规则修正仍可能需要人工或前复权数据源二次确认。

## 基础筛选与候选池

默认要求基金规模不少于1亿元，并主要用近20日成交额中位数检查约1000万元的流动性门槛。上市不足60天只标记数据不足；60至180天进入新ETF观察池；达到180天才进入正式策略池。近期涨跌幅不作为基础硬过滤，避免提前误杀反弹机会。

相同跟踪指数强制去重，代表产品优先看流动性、规模、历史长度和数据完整性。高相关产品只有在主题或跟踪指数也明显相近时才去重；不同主题即使阶段相关性很高也会保留。

## 每日完整工作流

### 1. 同步日线：历史缺口随时可补

无论白天、晚上、周末还是节假日，都可以执行：

```powershell
python main.py --sync-only
```

如果中间几天没有更新，普通命令会立即补齐到最近一个允许写入的完整交易日。交易日20:00前，时间门控只暂缓今天的日线，不会拦截前几天的历史缺口；20:00后才把今天纳入普通同步目标。周末和节假日会补到最近一个交易日。

正常日志大致如下：

```text
INFO etf_sync.engine - 数据库初始化完成：data/etf_daily.db
INFO __main__ - === 仅同步日线数据 ===
INFO etf_sync.sync - sync_etf_daily: 本地有 ... 只 ETF 的历史数据
INFO etf_sync.sync - ETF 日线同步完成: ...
INFO etf_sync.sync - 指数日线同步完成: ...
INFO __main__ - 同步完成: ETF ... 只, 指数 ... 个
```

`Tencent 失败，切换 Sina` 表示单只产品正在改用备用源，不等同于整个程序卡死。全市场约 1600 只 ETF，强制逐只检查时可能长时间没有汇总日志。

`--force` 主要用于交易日15:30后、20:00前确实要尝试取得当天日线：

```powershell
python main.py --sync-only --force
```

补前几天的数据不需要 `--force`。强制模式也不会让上游提前发布数据，运行后仍要核对当天记录数。`--backfill` 会重新抓取更长历史，耗时更大，只在首次建库或明确修复大量历史缺口时使用。

### 2. 核对行情截止日期

PowerShell 中请用外层双引号：

```powershell
python -c "import sqlite3; c=sqlite3.connect(r'data/etf_daily.db'); print(c.execute('SELECT date, COUNT(1) FROM etf_daily GROUP BY date ORDER BY date DESC LIMIT 3').fetchall())"
```

报告生成日期和行情截止日期是两个概念。周末、休市日或同步未完成时，今天生成的报告仍可能使用最近一个有效交易日。先核对数据库，再判断报告日期是否异常。

### 3. 运行全市场分析

```powershell
python -m etf_universe --config data\action-test-config.json --output data\universe_final_report
```

这个命令会读取数据库最新有效交易日，检查价格断层，完成正式 ETF 池和新 ETF 观察池划分，运行策略与历史验证，生成三赛道结果、风险和行动建议。

运行结束后会输出一个带时间戳的目录。日常主要查看其中：

- `ETF每日分析_YYYYMMDD.xlsx`：一个工作簿，多个中文 Sheet；
- `analysis_report.md`：便于快速阅读或版本追踪的文字汇总；
- CSV：保留给旧流程、调试和问题追溯，日常无需逐个打开。

### 4. 正确理解“关注”与“买入”

报告将两件事分开：

- **值得关注**：进入趋势、反弹或防守候选，包括等待回调、暂不追高、反弹观察、防守候选；
- **存在可执行买入信号**：只有规则明确允许执行的行动，例如“可以关注买入”或通过有效模型和止跌确认的反弹试错。

防守候选、等待回调和暂不追高不会让“今日存在可执行买入信号”变成“是”。系统允许当天没有可执行机会。

### 5. 有真实持仓时再启用卖出分析

先生成模板：

```powershell
python -m etf_universe --write-holdings-template data\etf_holdings.json
```

编辑 `data\etf_holdings.json` 后，再运行第 3 步的全市场分析。没有登记真实持仓时，报告会明确写：

```text
由于当前没有真实持仓数据，系统不生成个性化卖出建议。
```

这与“已经检查持仓且今天没有卖出信号”含义不同。

一个有效的人工持仓记录如下：

```json
{
  "version": 1,
  "holdings": [
    {
      "code": "560710",
      "name": "船舶ETF",
      "entry_date": "2026-09-01",
      "entry_price": 1.234,
      "quantity": 1000,
      "entry_type": "trend",
      "active": true,
      "entry_market_regime": "震荡 · 明显分化",
      "entry_strategies": ["趋势动量", "量价配合"],
      "entry_reason": "MA20高于MA60，且有效趋势策略支持"
    }
  ]
}
```

`entry_type` 支持 `trend`、`rebound`、`defensive`。程序也兼容中文“趋势、反弹、防守”和旧字段名。`active: false` 的记录不会参与当天分析。

如果还要读取原模拟盘状态：

```powershell
python -m etf_universe --config data\action-test-config.json --output data\universe_final_report --include-simulation-holdings
```

## 三个机会赛道

| 赛道 | 寻找什么                                 | 核心行动逻辑                                    |
| ---- | ---------------------------------------- | ----------------------------------------------- |
| 趋势 | 已经走强并得到趋势、突破或量价确认的 ETF | 要求中期趋势存在，同时避免短期追高              |
| 反弹 | 已经超跌并开始止跌修复的 ETF             | 不要求 MA20 大于 MA60，但必须检查止跌分和持续性 |
| 防守 | 波动、回撤和风险收益相对稳定的 ETF       | 关注风险特征，不因短期涨得慢而排除              |

反弹策略的历史验证分为“强、合格、弱优势、未通过”。弱优势策略可以把 ETF 放入“反弹观察”雷达，但不能单独触发“小仓反弹试错”。反弹信号始终表示短期修复机会，不代表中期趋势已经反转。

趋势和防守主要使用组合回测的风险收益、年化收益、最大回撤和稳定性。反弹额外检查信号后5日/10日收益、10日上涨概率、不利波动、盈亏比和样本量。验证样本少于120个共同交易日时显示低置信度，120至250日为中，超过250日为较高；“验证合格但置信度低”不能解读为结论稳定。

## 市场环境的两个维度

报告分别判断：

- **大盘状态**：强势、震荡偏强、震荡、震荡偏弱、弱势；
- **市场结构**：普遍走强、正常分化、明显分化、普遍走弱。

最终显示为类似 `震荡 · 明显分化`。前一个维度来自沪深300相对 MA60、MA250、均线方向和波动；后一个维度来自候选 ETF 的上涨占比、近 5 日与 20 日横截面离散度、强弱两端收益差。结构明显分化时，大盘震荡不会直接否定局部强主题。

## 策略支持数字

Excel 将三个分母分开：

- **有效策略支持**：支持该 ETF 的历史有效策略数 / 当前历史有效策略总数；
- **有效家族支持**：支持该 ETF 的历史有效策略家族数 / 当前历史有效家族总数；
- **全部家族覆盖**：支持该 ETF 的活跃策略家族数 / 当前正常运行的家族总数。

多个相似趋势策略可能属于同一家族，因此策略数和家族数不能混写。`2 / 2 个历史有效策略支持` 表示两个有效策略都选中了它；这仍不等于当前位置适合买入。

## ETF 风险

报告区分：

- **ETF 结构风险**：流动性、跨境/QDII、商品结构、折溢价、特殊交易机制和数据异常；
- **当前交易风险**：趋势强弱、短期过热、波动、止跌与反弹持续性。

港股通股票 ETF 单独标记，默认结构风险为“中”，并提示汇率、港股交易制度、交易日差异和港股通机制。跨境/QDII 在可靠折溢价数据缺失时显示“评估不完整”，最高行动等级会受到限制。

## 持仓与卖出闭环

卖出判断先检查“当初为什么买，现在是否仍成立”：

- 趋势持仓以趋势破坏、策略支持下降、过热和移动止盈为主；单日跌破 MA20 不会直接强制卖出；
- 反弹持仓以前低失守、止跌分下降、修复目标完成和默认 8 个交易日时间止损为主；
- 防守持仓以波动恶化并失去防守支持为主，不因涨得慢自动卖出。

系统可能输出继续持有、持有观察、可以考虑加仓、减仓锁利、止盈退出、止损退出、趋势破坏退出、反弹失败退出、时间止损退出或风险恶化退出，并附具体原因。它只生成提醒，不发送交易指令。

## Excel 工作簿

当前工作簿包含 12 个中文 Sheet：

| Sheet        | 内容                                                     |
| ------------ | -------------------------------------------------------- |
| 今日总览     | 大盘状态、市场结构、关注机会、可执行信号、主题代表和数量 |
| 趋势机会     | 趋势候选、策略/家族支持、均线、风险和行动                |
| 反弹机会     | 超跌支持、弱优势雷达、止跌分、持续性、风险和行动         |
| 防守机会     | 防守候选、风险收益、波动、回撤和行动                     |
| 新ETF观察    | 上市 60 至 180 天产品；只观察，不给最高级建议            |
| 持仓跟踪     | 已登记持仓的收益、原买入理由、当前支持和状态             |
| 卖出信号     | 只列需特别处理的已登记持仓；无持仓时明确不可评价         |
| 策略验证     | 验证等级、策略家族、样本、交易次数、成本和基准           |
| ETF筛选过程  | 各筛选阶段数量和淘汰原因                                 |
| 风险检查     | ETF 结构风险与当前交易风险明细                           |
| 数据异常检查 | 价格断层、修复方式、可信度和人工核验状态                 |
| 完整候选池   | 去重后的全部正式候选基础信息                             |

防守主题在“今日总览”中每个主题只显示一只代表 ETF，其余写为备选；防守机会详细 Sheet 保留全部候选。

## 当前限制

- 主要依赖技术面、成交、基金资料和历史价格，不自动理解所有新闻、政策和宏观事件；
- 市场环境、主题识别、数据断层和行动建议仍是透明规则，可能出现边界误判；
- 折溢价和部分基金资料受数据源可用性影响，缺失时会标为不可用或评估不完整；
- 短历史 ETF 只进入观察池，短样本结果不能与成熟 ETF 等价；
- 回测结果受样本长度、交易成本和市场阶段影响，不代表未来收益；
- 持仓分析依赖用户正确填写买入日期、价格、数量、机会类型和买入理由；
- 本项目不构成投资建议，也不承诺收益。
